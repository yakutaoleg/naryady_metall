# Спецификация: Управление сотрудниками (Админка)

**Дата:** 2026-08-18  
**Статус:** Approved  
**Автор:** собрано в диалоге с заказчиком

---

## Цель

Дать мастерам инструмент в Telegram-боте для управления сотрудниками: просмотр, активация новых, редактирование специализаций/роли, деактивация. Без SQL, без внешних инструментов.

---

## Доступ

- Только мастера (`role = 'master'`)
- Точка входа: кнопка **«👥 Сотрудники»** в главном меню мастера

---

## 1. Список сотрудников

**По умолчанию — только активные** (`is_active = true`).

```
👥 Сотрудники

[Иван Батура]       [Гусак Александр]
[Боричевский К.]    [Супрунюк А.]
...
[👤 Неактивные]     [📥 Заявки (2)]
```

- Если заявок нет: кнопка «📥 Заявки» не показывается
- Если заявки есть: «📥 Заявки (N)» с количеством
- Если сотрудников больше 8 — пагинация (стрелки «← →»), по 8 на странице
- Кнопка «👤 Неактивные» → отдельный список деактивированных

---

## 2. Карточка активного сотрудника

```
👤 Гусак Александр
@gusak_sasha

Роль: Рабочий
Специализации: ПИЛА, ПЛАЗМА

[✏️ Изменить имя]    [🎓 Специализации]
[👑 Изменить роль]   [🚫 Деактивировать]
[← Назад]
```

---

## 3. Изменить специализации

Чекбоксы из фиксированного списка: ПИЛА, ПЛАЗМА, СБОРКА, СВАРКА, СВЕРЛЕНИЕ, ГРУНТОВКА, ПОКРАСКА.

```
Специализации — Гусак Александр:

[✅ ПИЛА]       [✅ ПЛАЗМА]
[☐ СБОРКА]     [☐ СВАРКА]
[☐ СВЕРЛЕНИЕ]  [☐ ГРУНТОВКА]
[☐ ПОКРАСКА]

[💾 Сохранить]  [← Отмена]
```

- Тап на кнопку — тоггл (✅/☐), сообщение редактируется в месте
- Сохранить — обновляем `employees.specialization` (массив)
- Существующие наряды **не трогаем**
- Уведомления сотруднику **не отправляем**

---

## 4. Изменить роль

```
Роль — Гусак Александр:

[👷 Рабочий ✅]  [👑 Мастер]
[← Отмена]
```

- Текущая роль отмечена ✅
- Смена роли — обновляем `employees.role`
- Уведомления сотруднику **не отправляем**

---

## 5. Изменить имя

Бот пишет:
```
Введите новое имя для Гусак Александр:
(любой формат, например: Гусак Александр)
```

Мастер пишет текстом → бот сохраняет → показывает карточку с обновлённым именем.  
Валидация: **не нужна**, принимаем любую строку.

---

## 6. Деактивировать

```
Деактивировать Гусак Александр?

⚠️ У него 5 открытых нарядов. Они останутся на нём.

[✅ Да, деактивировать]  [← Отмена]
```

*(Если открытых нарядов нет — строка с ⚠️ не показывается)*

После деактивации:
- `is_active = false`
- Сотрудник при любом обращении к боту видит: `🚫 Ваш аккаунт деактивирован. Обратитесь к мастеру.`
- Наряды остаются назначенными на него

## 7. Список неактивных сотрудников

```
👤 Неактивные сотрудники

[Бойко Павел]  [Сидоров А.]
[← Назад]
```

Карточка неактивного:
```
👤 Бойко Павел
@boyko_p  · Неактивен

Роль: Рабочий
Специализации: СВАРКА

[✅ Активировать]  [← Назад]
```

При активации — просто ставим `is_active = true`.  
Уведомления сотруднику **не отправляем**.

---

## 8. Новый сотрудник — сценарий /start

### Шаг 1. Сотрудник пишет /start

Бот проверяет: `telegram_id` не найден в `employees` и нет активной заявки в `pending_users`.

Ответ сотруднику:
```
⏳ Ваша заявка отправлена мастеру. Ожидайте активации.
```

Запись в `pending_users` (status='pending').

**Если сотрудник пишет /start повторно** (пока заявка pending):
```
⏳ Ваша заявка уже отправлена. Ожидайте активации.
```
Новую заявку не создаём.

---

### Шаг 2. Все активные мастера получают уведомление

```
📥 Новый сотрудник хочет доступ:
Иван Батура (@ivan_b)

[✅ Одобрить]  [❌ Отклонить]
```

---

### Шаг 3. Мастер нажимает «Одобрить»

Если другой мастер уже одобрил — сообщаем: `ℹ️ Этот сотрудник уже активирован другим мастером.`

Иначе бот просит ввести имя:
```
Введите полное имя сотрудника
(как будет отображаться в нарядах):
```

---

### Шаг 4. Мастер выбирает специализации (чекбоксы)

```
Специализации — новый сотрудник:

[☐ ПИЛА]      [☐ ПЛАЗМА]
[☐ СБОРКА]    [☐ СВАРКА]
[☐ СВЕРЛЕНИЕ] [☐ ГРУНТОВКА]
[☐ ПОКРАСКА]

[💾 Далее]  [← Отмена]
```

*(Можно выбрать ноль — разрешено, специализации добавят потом)*

---

### Шаг 5. Мастер выбирает роль

```
Роль нового сотрудника:

[👷 Рабочий]  [👑 Мастер]
```

По умолчанию «Рабочий».

---

### Шаг 6. Подтверждение

```
Добавить сотрудника?

Имя: Батура Илья
Роль: Рабочий
Специализации: СБОРКА, СВАРКА

[✅ Добавить]  [← Изменить]
```

---

### Шаг 7. Результат

Мастеру:
```
✅ Батура Илья добавлен.
```

Сотруднику — уведомление **не отправляем**. Он при следующем обращении к боту получит доступ автоматически.

---

### Шаг 8. Мастер нажимает «Отклонить»

Запись в `pending_users`: `status = 'rejected'`.

Другие мастера видят у себя кнопки заблокированными: `ℹ️ Заявка уже обработана.`

Сотруднику — уведомление **не отправляем**.

---

## 9. Повторный /start от деактивированного пользователя

Если `telegram_id` есть в `employees` и `is_active = false`:

- Создаём запись в `pending_users` (status='pending'), **только если такой записи ещё нет**
- Если запись уже существует (статус pending/rejected/approved) — просто отвечаем: `⏳ Ваша заявка уже отправлена. Ожидайте.`
- Мастера получают уведомление (как в п.2), но с пометкой: `(ранее был зарегистрирован)`
- Мастер одобряет → `is_active = true`, данные сотрудника обновляются (имя, роль, специализации) через тот же флоу

## БД — новая таблица

```sql
CREATE TABLE pending_users (
    id           serial PRIMARY KEY,
    telegram_id  bigint NOT NULL,
    username     text,
    first_name   text,
    last_name    text,
    requested_at timestamptz DEFAULT now(),
    status       text DEFAULT 'pending'  -- pending / approved / rejected
    -- Уникальность: один активный pending на одного пользователя
    -- (проверяется в коде, не уникальным индексом — история нужна)
);
```

## Что НЕ входит в скоуп

- Удаление сотрудника из БД (только деактивация)
- История изменений (кто что менял)
- Перенос нарядов при деактивации
- Редактирование списка специализаций через бот
- Поиск по имени
- Уведомления сотрудникам при изменении данных
