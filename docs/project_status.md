## Количество деталей на сборку (22.10.2026, внедрено на проекте 103 «ЛИДСКАЯ ПМК - 169 ОБЩИЙ - наряды»)
- Лист ЗАВИСИМОСТИ: колонки F «ДЕТАЛЬ» и G «КОЛ-ВО НА 1 СБОРКУ» (строка: СБОРКА | сборка | ПЛАЗМА/ПИЛА | сборка | деталь | штук на 1 сборку). Строки без F/G работают по прежней пропорциональной логике.
- Расчёт: свободно(деталь) = выполнено − Σ(штук на сборку × выполнено сборок); можно ещё = min по деталям (свободно // нужно). Один модуль src/deps_parts.py используют sync (_compute_block, _reconcile_blocks) и бот (_deps_ready, _deps_blocking, _deps_available_qty, _available_qty_map).
- БД: element_dependencies.part, qty_per (migrations/2026-10-22_element_dependencies_parts.sql).
- Мастер проектов: шаг после перезаписи ЗАВИСИМОСТИ (component_deps.fill_component_deps из файла сборок), в итоговом сообщении предупреждения о нехватке деталей.
- Старый проект: `python -m src.component_deps ID --dry-run` (сухой прогон), без флага запись; затем `python src/sync.py --project ID --force`. Отчёт «что изменится в БЛОК»: `python src/component_report.py ID`.
- Ночная проверка: consistency_check.check_components (деталь не найдена, сборка без количества, дубли, нехватка деталей, собрано больше, чем изготовлено).
- Откат для проекта: очистить строки с заполненной колонкой F в ЗАВИСИМОСТИ (или восстановить из backup/zavisimosti_ID_*.json) и `sync.py --project ID --force`.
- Известно: у бота и sync раньше были разные реализации блокировки (бот сопоставлял метку сборки только точным совпадением и не видел списки через запятую в колонке ЭЛЕМЕНТ). Для проектов с количеством деталей теперь везде единый расчёт; остальные проекты работают как раньше.
