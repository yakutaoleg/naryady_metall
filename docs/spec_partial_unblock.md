# Фича: Частичная разблокировка (Partial Unblocking)

**Статус:** В ПЛАНЕ — не реализовано  
**Дата постановки:** 2026-08-13  
**Приоритет:** Высокий (запрос клиента)

---

## Суть задачи

Сейчас система работает по принципу "всё или ничего": СБОРКА (или другой downstream-лист) заблокирована до тех пор, пока все детали в ПИЛА/ПЛАЗМА не нарезаны на 100%.

Клиент хочет: если нарезана часть деталей (например 5 из 10) — сборщик должен видеть что уже можно начинать на эти 5 штук, а не ждать все 10.

---

## Пользовательский сценарий

**Пример:** деталь Ф-1 в проекте Нефтеспецстрой ОСИ 4-10.
- СБОРКА: Ф-1 = 10 шт, заблокирована ПЛАЗМОЙ
- В ПЛАЗМЕ нарезано 5 из 10 комплектов деталей Ф-1

### Как будет выглядеть в Google Sheets (лист СБОРКА):

**Сейчас:**
```
Ф-1 | 10 шт | ПЛАН | ⛔ ПЛАЗМА
```

**После:**
```
Ф-1 | 10 шт | ПЛАН | ✅ 5 из 10
                     ⛔ ПЛАЗМА
```

### Как видит рабочий в боте:

Позиция показывается с префиксом `✅ 5 из 10` вместо `⛔`.
Рабочий нажимает "◧ Частично" → вводит число → **валидация: максимум 5** (по количеству доступных).

### После того как рабочий выполнил 5 шт (ЧАСТИЧНО):

Строка в СБОРКЕ раздваивается — оба ряда получают одинаковый БЛОК:
```
Ф-1 | 5 шт | В РАБОТЕ | ✅ 5 из 10 / ⛔ ПЛАЗМА
Ф-1 | 5 шт | ПЛАН     | ✅ 5 из 10 / ⛔ ПЛАЗМА
```

Первая строка (5 шт выполнено) → **автоматически триггерит СВАРКУ на 5 шт** (тот же механизм что сейчас).

---

## Критический баг (существует уже сейчас, нужно исправить в рамках фичи)

`_deps_ready()` в bot.py считает **количество строк** с ВЫПОЛНЕНО, а не **суммарное qty**.

При частичной нарезке ПИЛА: строка сплитится → ВЫПОЛНЕНО(5шт) + ПЛАН(5шт).
`_deps_ready()` видит "есть строка ВЫПОЛНЕНО" → возвращает `True` → **СБОРКА полностью разблокируется**.
Рабочий может нажать "Выполнено все 10 шт" хотя нарезано только 5.

## Новая функция `_deps_available_qty()` — псевдокод

```python
def _deps_available_qty(project_name: str, element: str, sheet_name: str) -> tuple[int, int]:
    """Возвращает (qty_available, qty_total) из upstream-листов.
    qty_available = сумма quantity строк со статусом ВЫПОЛНЕНО
    qty_total = сумма quantity всех строк upstream
    """
    deps = db.fetchall(
        "SELECT requires_sheet, requires_position FROM element_dependencies "
        "WHERE project_name=%s AND element=%s AND waiting_sheet=%s",
        [project_name, element, sheet_name]
    )
    if not deps:
        return (0, 0)  # нет зависимостей

    # Берём минимум по всем зависимостям (узкое место)
    # Если деталь зависит от ПИЛА и ПЛАЗМА — считаем отдельно и берём min
    min_ratio = 1.0
    ref_total = None
    for dep in deps:
        rows = db.fetchall(
            "SELECT status, quantity FROM work_orders "
            "WHERE project_name=%s AND sheet_name=%s AND element=%s",
            [project_name, dep['requires_sheet'], dep['requires_position']]
        )
        done_qty = sum(int(r['quantity'] or 0) for r in rows if r['status'] == 'ВЫПОЛНЕНО')
        total_qty = sum(int(r['quantity'] or 0) for r in rows)
        if total_qty > 0:
            ratio = done_qty / total_qty
            if ratio < min_ratio:
                min_ratio = ratio
                ref_total = total_qty  # сохраняем total от bottleneck-зависимости
    
    # Нужно вернуть количество в единицах СБОРКИ (а не upstream)
    # Для этого нужно знать qty сборки — передаётся снаружи или читается из work_orders
    return (available_qty, assembly_qty)
```

> **Важный нюанс:** `_deps_available_qty` должна работать в единицах СБОРКИ (10 шт), а не upstream (40 косынок). Поэтому нужно знать qty детали в СБОРКЕ. Варианты: передавать как параметр, или читать из work_orders.
