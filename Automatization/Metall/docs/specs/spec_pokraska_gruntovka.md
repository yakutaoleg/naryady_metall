## 1. Архитектурное решение

Переиспользуем существующую универсальную архитектуру системы без структурных изменений:
- `WORK_SHEETS` в config.py управляет списком специализаций — достаточно добавить строку
- `sync.py` итерируется по `WORK_SHEETS` — новые вкладки подхватятся автоматически
- Механизм зависимостей (`element_dependencies` + лист ЗАВИСИМОСТИ) уже работает для любых пар специализаций
- Единственные хардкоды требующие исправления: проверки `== 'СБОРКА'` в bot.py (2 места)

Полный производственный цикл после реализации:
```
ПЛАЗМА/ПИЛА → СБОРКА → СВАРКА → ПОКРАСКА → ГРУНТОВКА
```

## 4. Flow диаграмма (основной сценарий)

```
[Мастер создаёт наряд в Sheets]
    ↓
[Заполняет вкладки: ПОКРАСКА, ГРУНТОВКА]
[Заполняет ЗАВИСИМОСТИ: СВАРКА→ПОКРАСКА, ПОКРАСКА→ГРУНТОВКА]
    ↓
[sync.py (каждые 15 мин)] → читает ПОКРАСКА, ГРУНТОВКА → UPSERT в work_orders
    ↓
[Рабочий-маляр: /start в боте]
    ↓
[get_active_tasks → для sheet_name в SHEETS_WITH_DEPS вызывает _deps_ready]
    → _deps_ready: проверяет element_dependencies → есть строка СВАРКА→ПОКРАСКА
    → проверяет work_orders: status='ВЫПОЛНЕНО' для СВАРКА по этой позиции
    → если нет → deps_ready = False → задача показывается с иконкой ☐ (недоступна)
    → если да  → deps_ready = True  → задача доступна
    ↓
[Маляр нажимает "Выполнено"]
    → status='ВЫПОЛНЕНО' в БД и Sheets
    → notify_deps_unblocked проверяет element_dependencies
    → находит ПОКРАСКА→ГРУНТОВКА
    → разблокирует задачу ГРУНТОВКИ (БЛОК→ПЛАН или создаёт доступность)
    → уведомляет грунтовщика если назначен
    ↓
[Рабочий-грунтовщик видит задачу как доступную]
```

## 5. Edge Cases и обработка ошибок

| Сценарий | Ожидаемое поведение |
|---|---|
| Вкладка ПОКРАСКА/ГРУНТОВКА отсутствует в файле | sync.py пропускает (WorksheetNotFound), логирует info — не ошибка |
| Элемент в ПОКРАСКА без записи в ЗАВИСИМОСТИ | `_deps_ready` вернёт True — задача доступна сразу (нет ограничений) |
| Несколько позиций одного элемента в СВАРКА | `_deps_ready` проверяет ВСЕ строки с этой позицией/элементом — все должны быть ВЫПОЛНЕНО |
| Рабочий не зарегистрирован в СОТРУДНИКИ | Бот выдаст "Вы не найдены в системе" — стандартное поведение |
| Маляр нажимает на задачу с deps_ready=False | Бот показывает alert "☐ Ожидает готовности предыдущего этапа" — не открывает карточку |
| Грунтовщик видит БЛОК (ПОКРАСКА не завершена) | Стандартный флоу блока: мастер снимает вручную или автоматически через notify_deps_unblocked |

## 6. Технические ограничения

- `_deps_ready` проверяет по полям `element` и `position` — мастер должен вносить в ЗАВИСИМОСТИ значение точно совпадающее с содержимым колонки ЭЛЕМЕНТ или ПОЗ. СОГЛАСНО ЧЕРТЕЖА
- sync.py обновляет колонку БЛОК в Sheets — для этого в вкладках ПОКРАСКА/ГРУНТОВКА должна быть колонка с заголовком `БЛОК`
- Лист ЗАВИСИМОСТИ нужно заполнить вручную для каждого объекта — автоматической генерации нет (это вне скоупа)
- Изменения в bot.py вступают в силу только после рестарта сервиса на VPS

## 10. Оценка сложности

- **Сложность: Low**
- Затронуто файлов: 2 (config.py, bot.py)
- Изменений в коде: ~10 строк
- Новых компонентов: 0 (только расширение существующих)
- Тест-сценариев для AQA: 12

**Риски реализации:**
- Два хардкода `== 'СБОРКА'` в bot.py — оба должны быть заменены; пропуск одного приведёт к тому, что задачи ПОКРАСКА/ГРУНТОВКА будут видны даже при незавершённых зависимостях
- Мастер должен вручную заполнить ЗАВИСИМОСТИ для каждого объекта — без этого блокировки не работают, но бот работает корректно (задачи доступны сразу)
- Эталонную структуру колонок для новых вкладок взять из реального листа СВАРКА (не из кода) — убедиться что заголовки точно совпадают, иначе sync не распознает колонки
